# GSR 0.6.0 — candidate release notes

Status: prepared candidate; not yet published. Live model and browser validation remain outstanding.

## Changes

- Phase 1: repaired installed hooks, shared project discovery, configured checks and source-bound verification records. Failed, unavailable and stale results remain visible.
- Phase 2: focused-feature entry, task coordination, reusable research, installed-skill selection and bounded context handoffs.
- Phase 3: previews before implementation, decision/feedback records, resume and progress reporting; includes a booking preview and a working JSON-to-CSV example.
- Phase 4: change-impact maps, task context packages, durable sequential queues with bounded retries and before/after outcome reports.
- Corrections V1–V5: complete required-check coverage, navigation-safe freshness, focused-feature status, equivalent documentation paths and reference ambiguity limited to the requested heading.
- Release tooling synchronizes both lockfile root versions, checks version drift and stages only release metadata. Installation checks use the public 0.5.0 tag and can preserve the exact candidate version.

## Install or update

After publication, a new installation uses:

```sh
claude plugin marketplace add https://github.com/kmajerowicz/get-shit-right
claude plugin install gsr@gsr
```

An existing installation uses:

```sh
claude plugin marketplace update gsr
claude plugin update gsr@gsr
```

Restart the tested Claude Code 2.1.274 session and check the installed version. For newer clients, follow the activation/reload message; see the [official installation and update guide](https://code.claude.com/docs/en/discover-plugins). Existing users can also follow `/gsr:update`, whose published-version path still requires rollout verification.

## Supported observations and limits

Native startup and local installation checks were observed with Claude Code 2.1.274 on macOS and Node 26. CI covers Ubuntu and Node 22. This does not establish Windows or Codex compatibility.

Autopilot keeps one active queue per project. Context transitions require explicit user continuation; it does not automatically create new model sessions. Checkpoints and check records are not human acceptance or proof of semantic correctness. Model costs remain unknown; no time or cost savings are claimed.

## Recovery

If a critical issue appears after rollout, disable the plugin in the installation's scope using `claude plugin disable gsr@gsr`, preserve project decisions/queues and report the installed version and reproduction. Restore copied statusline settings only from a known backup while preserving unrelated settings. Prefer a forward fix; do not rewrite published tags or assume downgrade preserves new queue formats.
