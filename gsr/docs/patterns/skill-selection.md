# Relevant installed guidance

Selection is agent reasoning from the task/output and host-exposed current skill
catalog, not keyword classification. Reuse relevant installed guidance first. Load
its actual SKILL.md and use applicable instructions within the user's scope. A saved
name/table or matching technology word is not proof that it was loaded or followed.
No routine selection approvals and no inferred installation/publishing/payment authority.

## Select, load and record

1. Inspect task needs/current conventions and catalog availability. Respect explicit
   user skill requests. Match actual capability/output; reject an irrelevant keyword hit.
2. Load relevant available guidance before the step needing it. Reuse already loaded
   current content in the same task; do not repeatedly search marketplaces/catalogs for
   an unchanged correction. Do not assume a remembered skill is still installed.
3. Record only useful navigation in the existing feature Task Context, plan's Skills
   Confirmed section or techstack for truly project-wide guidance: name/provider, source
   from the actual catalog, task applicability, available version or content identity,
   and loaded/use observation/limit. If version/identity is unavailable write unknown,
   not an invented value. Keep the plan headings/table intact for progress normalization.
4. At fresh-context resume compare the saved need with current catalog/guidance. Read
   the current source if available; a previous session's loaded text is not assumed in
   the new context. Changed content/source needs reconciliation, not automatic reinstall.
   Skill paths outside the project are resolved through the catalog, never arbitrary
   packet Read next paths. Project-held requirements/guidance remain fingerprint inputs;
   external catalog sources have separate availability observations, not remote proof.

## Capability gaps

- Optional skill missing: use available tools/guidance/docs, continue authorized work
  and report only a relevant limitation. Missing design skill alone does not demand install.
- Essential capability unavailable: name the specific needed executable/access and
  consequence. Ask only for that actual permission/information; continue independent work.
- External discovery: only for a concrete uncovered need, through already permitted tools.
  Never invoke a package-fetching CLI merely to search when install is not authorized.
- Installation denied: keep the boundary; no alternative downloader, account creation,
  paid call or model switch to bypass it. Skills do not grant external-action authority.

Names/provider/applicability are navigation, not team policy or a new global preference.
Do not promote a personal preference into shared Learned Rules silently. Avoid default
marketplace/model/installed-path assumptions. Real skill use and benefit require task
observations; reference/metadata tests alone cannot prove them.
